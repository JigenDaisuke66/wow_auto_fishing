# 识别与优化方案

## 当前咬钩方案

旧实现只比较相邻两帧的平均灰度差。水面持续运动时，相邻帧容易误触发；浮漂缓慢下沉时，相邻帧差异又可能一直偏小。

当前实现改为：

1. 找到浮漂后保存一张经过灰度化和高斯降噪的基线图。
2. 后续画面始终与基线比较，而不是仅与上一帧比较。
3. 平均差异达到阈值只是条件之一。
4. 还要求达到指定比例的像素发生显著变化。
5. 两个条件必须连续满足若干帧后才收杆。

新配置推荐先使用默认参数，根据日志逐步调整：误触发时提高“变化像素比例”或“连续确认帧数”；漏检时优先降低平均差异阈值。旧版配置中的平均差异阈值会原样保留，不会被迁移过程覆盖，建议旧用户在界面中重新校准。

## 仍可继续改进

### 1. 声音检测

若游戏的咬钩音效稳定，可以捕获系统音频并匹配声音特征。声音通常比水面视觉变化稳定，但实现复杂，且会受音量、其他音效和音频设备影响。

### 2. 运动方向与形态

使用光流或轮廓跟踪，判断浮漂是否快速向下移动，而不是只判断画面变了。这更符合咬钩语义，但需要更稳定的浮漂区域和更多测试样本。

### 3. 多尺度模板

当前模板匹配对界面缩放和视角距离敏感。可以预生成多个比例的模板，或换用 ORB 特征匹配，但会增加运算量。

### 4. 自适应阈值

抛竿后的前几秒采集水面噪声，自动计算背景波动范围，再动态设置阈值。它比固定阈值适应性更好，但需要避免把早期咬钩样本当作背景。

### 5. 搜索区域进一步收缩

当前已从全屏缩到游戏窗口。若浮漂通常落在固定画面区域，可再提供可视化 ROI 选择，显著降低 CPU 占用与误匹配。

## 性能注意事项

- 模板越小、数量越少，匹配越快。
- 截图应只包含有辨识度的浮漂部分，但不能小到缺乏纹理。
- 游戏窗口分辨率越高，模板匹配成本越大。
- 日志每 0.1 秒更新可能带来额外界面开销，后续可增加日志采样频率设置。
